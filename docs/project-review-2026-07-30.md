# Enterprise AI Cockpit 项目审阅（2026-07-30）

## 结论

项目已经从“可演示的页面壳”补齐为可运行的 RAG 链路：浏览器请求经过 Java
关键操作验证，按请求选择 DeepSeek 模型，检索 MySQL/pgvector 中的业务知识，
按需调用 MCP，并通过 SSE 返回答案、工具轨迹与引用。远端发布前的基线检查显示
服务进程原本在线，但知识库、文档、分块和向量行数全部为 0，MCP 也处于关闭
状态；这正是页面看起来可用、实际没有业务内容的主要原因。

本轮没有发现仍会阻止座舱启动或 RAG 对话的 P0 问题。剩余工作主要集中在生产
级身份体系、检索质量、异步补偿和仍为 Mock 的外围模块。

## 本轮已修复

| 优先级 | 原问题 | 处理结果 |
| --- | --- | --- |
| P0 | 对话没有请求级模型选择，部署配置只能固定一个模型 | 增加模型白名单与 `/api/chat/options`，支持 `deepseek-v4-flash`、`deepseek-v4-pro` 动态路由 |
| P0 | 远端知识库、MySQL 文档和 pgvector 全为空 | 增加幂等演示数据脚本，按业务创建 3 个知识库和 5 篇文档，并在导入时同步向量 |
| P1 | MCP 只有布尔开关，天气数据为静态示例，发布包也不包含 MCP 服务 | 增加天气、时区、安全计算器目录；天气接入 Open-Meteo；发布包携带 STDIO 服务并启用 Node.js |
| P1 | RAG 对话不使用历史消息 | 每轮带入同一会话最近 8 条消息，同时仍以当前问题执行检索 |
| P1 | 知识库缺少业务边界 | MySQL 增加 `business_type` 迁移，前端可按客户服务、跨境电商、量化研究等业务创建和选择 |
| P1 | 关键操作只有通用前端提示，交互粗糙 | 保留 Java HMAC 短期令牌接口，改为当前标签页有效的自定义验证弹窗；口令和签名密钥不进入 Git |

| P2 | ECharts 整包进入前端 | 改为按图表和组件注册，降低图表 vendor 体积 |

## 仍需修复与优化

### P1：生产身份、授权与审计

当前关键操作使用一个共享口令换取 30 分钟 HMAC 令牌，适合个人演示和受控环境，
不适合多人生产。下一步应接入真实账号、RBAC、租户/业务域授权、操作审计、
登录与验证限流、密钥托管及令牌吊销。聊天本身会产生模型费用，也应按用户或
来源增加配额与速率限制。

### P1：向量一致性补偿

MySQL 是事实来源，pgvector 写入失败时当前会记录警告并回退关键词检索，但不会
自动补写。应增加 outbox/任务表、重试与死信状态，并提供按文档或知识库重建向量
的管理操作；健康检查也应区分“数据库可连接”和“关系分块与向量行数一致”。

### P1：外围模块仍为 Mock

`DataSourceService` 只检查配置并返回固定快照；`ReportService` 没有按模板注册
真实 cron，也没有实际抽取数据或调用分析模型；`SpeechService` 返回伪 WAV。
这些页面应在 UI 明确标记为 Preview，或按业务优先级逐个实装，避免使用者把
示例输出误认为真实结果。

### P2：检索质量

默认 1536 维 local embedding 是确定性哈希实现，适合验证 pgvector 链路，但
不等于生产语义模型。后续应接入稳定的中文/多语 embedding，增加分段重叠、
BM25/向量混合召回、metadata 预过滤、重排、相似度阈值和离线评测集。当前向量
检索先取 top-k 再做 metadata 过滤，过滤条件较多时可能少返回结果，应在 SQL
层过滤或扩大候选集。

### P2：模型可靠性与成本控制

当前已区分 Flash/Pro 输出预算，但还缺少供应商超时分级、熔断、重试策略、
备用 key 切换、token/费用统计和敏感信息脱敏。Pro 的推理阶段会消耗更多输出
预算，建议在 UI 展示成本提示，并为普通问答默认使用 Flash。

### P2：可观测性与契约

需要补充 traceId、结构化日志、Micrometer 指标、上游模型耗时、检索耗时、
MCP 调用耗时、SSE 客户端中断指标，以及前后端 OpenAPI/契约测试。当前浏览器
测试使用真实流程验证，但还没有纳入持续集成。

### P2：部署资源策略

服务器总内存约 1.8GiB，座舱 JVM 的 `MemoryMax` 为 320MB。博客项目的资源
采样器在持续高负载时会主动禁用座舱，这是既有保护策略，但容易被误判为故障。
建议把“资源保护暂停”与“进程异常”分别展示，并提供告警和受控恢复入口。

## 验证基线

- 后端：Java 17、Spring Boot 3.5.3、Spring AI 1.0.0。
- 前端：Vue 3、Vite、Element Plus、ECharts。
- 远端：Nginx、MySQL/MariaDB、PostgreSQL 11.15 + pgvector 0.4.4。
- 实测链路：Flash/Pro 真实上游调用、WebFlux SSE、Java 操作令牌、MCP
  JSON-RPC、Open-Meteo、知识库导入、引用返回、浏览器验证弹窗。
- 发布要求：`mvn test`、`npm run build`、敏感信息扫描、仅座舱发布后的
  服务/页面/数据库/向量/MCP/两模型回归。
