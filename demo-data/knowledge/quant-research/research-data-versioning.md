# 量化研究数据版本与可复现性规范

## 数据快照

每次研究使用不可变数据快照。快照记录数据源、覆盖日期、字段定义、抓取时间、清洗代码版本和校验摘要。原始层只追加不覆盖，清洗层由代码生成；发现错误时创建新版本并说明修复内容，不能直接修改旧结果。

行情、财务、公司行动、指数成分、新闻和宏观数据分别维护版本。跨数据源连接时保存映射表版本，例如证券代码变更、退市和公司合并。所有时间字段注明时区及含义，区分事件发生、来源发布、系统获取和策略可用时间。

## 研究任务状态

研究任务经过已创建、数据就绪、运行中、完成、失败和已归档等状态。每次状态变化记录时间和原因。失败任务保留日志与输入，不把部分结果伪装成完成。重新运行生成新的 run ID，并关联原任务。

模型、因子、回测和报告都引用同一个 run ID。研究人员应能从一张结果图回到配置、代码、数据快照和原始输入。不能复现的高收益结果只作为线索，不进入策略评审。

## 配置与环境

配置文件保存股票池、日期、频率、参数、成本、基准和风险约束。密钥、密码和 token 不写入配置版本，而由运行环境注入。依赖版本、操作系统、运行镜像或 JDK/Python 版本一并记录。

随机过程固定种子，但也要使用多个种子检查稳健性。并行计算需要保证聚合顺序或记录可能的数值差异。正式结果输出机器可读摘要和人类可读报告。

## AI 研究辅助

AI 可以整理文献、生成实验草案、解释日志和把文本转成结构化事件，但生成内容必须保留提示词、模型与输入来源。AI 建议不能自动修改已冻结的测试方案；任何代码改动进入正常代码审查和测试流程。

知识库中的研究结论标记适用市场、数据期间、策略版本和风险边界。过期结论不删除，改为归档并链接替代版本，避免后来者重复走旧路径。

## 交付清单

正式研究包至少包含数据清单、代码提交、配置、运行日志、绩效指标、图表、异常说明和评审结论。评审人应能在隔离环境重跑主要结果。若数据授权不允许复制，则保存可验证的清单和重建步骤。
