# LLM 舆情因子的 Walk-forward 验证方法

## 模型职责

大模型不直接决定仓位，而是把新闻、公告和社交文本转换为可审计事件。每条事件保存标的、事件类型、方向、强度、置信度、原文证据、发布时间、处理时间和模型版本。无法确定标的或时间的文本不得进入交易因子。

结构化输出需要固定 schema，并验证枚举、数值范围和必填字段。模型给出的理由必须引用原文片段，不能把外部常识混成事实。相同内容被多个渠道转载时要去重，避免一个事件被重复计权。

## 时间纪律

因子时间使用系统真正获取并完成解析的时间，而不是媒体页面后来显示的编辑时间。收盘后事件只能影响下一交易日。盘中策略还要计入抓取、推理、风控和下单延迟。时区统一保存为 UTC，同时保留来源时区。

训练与验证按时间顺序进行。不能用后来的市场反应修改早期事件标签，再把修改后的标签用于历史回测。提示词变更、模型升级和分类规则调整都产生新版本，旧实验保持不变。

## Walk-forward

设置连续滚动窗口：在训练窗口确定事件映射、衰减和组合规则，在紧随其后的验证窗口评估，然后整体向前移动。每个窗口只使用当时可见数据。最终汇总各窗口表现，而不是只选择最好的一段。

对照实验至少包括不使用舆情因子的基准策略、规则词典因子和 LLM 因子。三组使用相同股票池、成本、风险预算与成交假设。增量价值看净收益、最大回撤、换手和尾部风险，不只看分类准确率。

## 失败窗口

若多个窗口为负，不应立即扩大模型或修改测试期。先分析市场状态变化、事件衰减、来源偏差、重复新闻和交易成本。解释只是新的假设，必须在后续未见数据中验证。

置信度高不等于收益高。模型的置信度只描述文本分类确定性，仓位由独立风险规则决定。出现数据中断、事件量异常或模型输出格式错误时，因子权重降为零，策略回退到基准。

## 上线条件

上线前要求事件可追溯、版本可复现、多个样本外窗口具有稳定增量、成本压力测试通过，并设定监控与下线阈值。本文是研究治理方法，不构成投资建议。
